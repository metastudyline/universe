# R28: 重借用（Reborrowing）与两阶段借用：`&mut *r` 解引用与方法调用隐式升级

> **一手编译器 RFC 与规范锚点**：Rust RFC 2094 (Two-Phase Borrows) · Rust Reference (Reborrowing)

---

## 1. 历史语境与问题发生学

在早期的 Rust（1.0 时代）中，许多直觉上完全安全的代码会被编译器严厉拒绝。最臭名昭著的反例就是向容器插入自身长度：

```rust
let mut vec = vec![1, 2, 3];
vec.push(vec.len()); // 早期 Rust 报错：无法在 vec 被可变借用时再次不可变借用！
```

为什么会报错？
因为 `vec.push(...)` 会先借用 `&mut vec` 作为接收者（Receiver），紧接着计算参数 `vec.len()` 时又试图借用 `&vec`。在传统借用模型中，两者在时序上发生重叠，违反了「别名异或可变性」。

为了解决这个符合人类直觉的语言痛点，Rust 编译器在 NLL 中正式引入了**两阶段借用（Two-Phase Borrows）**。

---

## 2. 状态机模型：预留态（Reserved）与激活态（Active）

```
vec.push(vec.len());
│        ▲
│        │ Phase 1: 预留阶段 (Reservation)
│        │ `&mut vec` 仅登记为预留借用，尚未执行任何内存写入
│        │ 此时允许共享读借用 `vec.len()` 安全执行！
│
▼
Phase 2: 激活阶段 (Activation)
参数计算完毕，控制流到达 `push` 入口，`&mut vec` 正式升级为独占可变借用！
```

---

## 3. 隐式重借用（Reborrowing `&mut *r`）

很多初学者容易误以为 `&mut T` 是可以像 `Copy` 一样到处乱传的。事实上：**`&mut T` 绝没有实现 `Copy` 特质！**

当执行如下代码时：

```rust
fn step(x: &mut i32) { *x += 1; }

let mut val = 10;
let r = &mut val;
step(r); // 为什么这里没有 Move 掉 r？
*r += 2; // 为什么这里还能用 r？
```

编译器的内部脱糖（Desugaring）：
编译器在 `step(r)` 处自动插入了 **`step(&mut *r)`**——它并不是移动了 `r` 这个指针本身，而是通过解引用再借用，派生出了一个生命周期更短的子借用。在子借用存活期间，父借用 `r` 暂时冻结；一旦 `step` 返回，`r` 自动解冻并重新获得独占权。

---

## 4. 形式化论证三段论 (Formal Syllogism)

- **大前提 ($P_1$)**：方法调用与表达式参数求值具有严格的时序先后性，在真正执行写入指令之前，预留的可变借用不会对只读查询造成数据污染。
- **小前提 ($P_2$)**：两阶段借用与重借用将借用生命周期的粒度从语句级细化到求值微步（Micro-step），且在激活时刻维持独占不变性。
- **归谬 ($R$)**：若不区分预留与激活而机械禁止参数求值中的只读借用，或者允许并发真正的可变写入，则语言将陷入极度冗余的临时变量声明或引发迭代器失效。
- **结论 ($C$)**：∴ 重借用与两阶段借用在不破坏任何底层内存安全公理的前提下，实现了形式化严密性与人体工学表达力的完美平衡。
