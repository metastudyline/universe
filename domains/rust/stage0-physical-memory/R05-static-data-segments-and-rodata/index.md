# R05: 静态段与只读常量：Text, Data, BSS 与 .rodata 的物理装载

> **一手文献与源码锚点**：Executable and Linkable Format (ELF) Specification (Book I: Executable and Relocatable Object Files)

---

## 1. 一手二进制布局：可执行文件的段装载

当操作系统加载可执行文件时，静态段直接映射进虚拟内存：

```
+-------------------------------------------------------------+
| .text 段   | 机器指令代码 (RX 权限: 允许读取、允许执行、禁止写入) |
+-------------------------------------------------------------+
| .rodata 段 | 只读常量字符串、虚表 (R 权限: 仅允许读取、禁止写入) |
+-------------------------------------------------------------+
| .data 段   | 已初始化静态变量 (RW 权限: 允许读取、允许写入)       |
+-------------------------------------------------------------+
| .bss 段    | 未初始化全局变量 (RW 权限: 内核清零页零页映射)       |
+-------------------------------------------------------------+
```

- **`'static` 的物理真相**：所谓的 `'static` 生命周期，本质上就是指针直接指向了 `.rodata` 或 `.data` 段，在进程启动时由操作系统内核装载，并在进程退出前永远不会被销毁。

---

## 2. 形式化论证三段论 (Formal Syllogism)

- **大前提 ($P_1$)**：硬件 MMU 对 `.rodata` 段设置了硬件级的只读位（Read-Only Page Flag），任何写入尝试都将由硬件直发非法访问异常。
- **小前提 ($P_2$)**：Rust 中的静态常量和字符串字面量在编译期被直接写入 `.rodata` 段。
- **归谬 ($R$)**：若语言允许对字符串字面量强行转型为可变指针并执行写入（如 C 语言 `char *s = "hello"; s[0] = 'H';`），则必然在运行期触发瞬间段错误崩溃。
- **结论 ($C$)**：∴ 字符串字面量在 Rust 中被严格赋予不可变共享引用 `&'static str`，在类型系统层面彻底杜绝了非法静态写入。
