# R04: 堆（Heap）的物理代偿：分配器算法（Bump/Free List/Slab）与多线程锁竞争

> **一手文献与源码锚点**：Jason Evans (2006) *A Scalable Concurrent malloc(3) Implementation for FreeBSD (jemalloc)* · Linux 内核 `mm/slab.c`

---

## 1. 一手硬件与算法剖析：堆分配的三重物理代偿

与栈单指令 RSP 步进截然不同，堆内存必须由运行期复杂的**内存分配器（Memory Allocator）**接管：

```
应用程序调用 malloc(64)
       ↓
[ 1. 线程局部缓存 (tcache) ] ──(命中: 零锁)──➔ 返回内存指针 (~5ns)
       ↓ (未命中)
[ 2. 线程所在 Arena 分配区 ] ──(互斥锁抢占 pthread_mutex_lock)──➔ 发生锁争用 (~50ns~1µs)
       ↓ (内存耗尽)
[ 3. 操作系统内核系统调用 ] ──(mmap / brk 陷入内核态)──➔ 分配物理页并修改页表 (~10µs)
```

- **代偿 1（时间延迟）**：小对象分配也可能因锁争用与内核系统调用带来数微秒级抖动；
- **代偿 2（空间碎片化）**：内存外碎片（External Fragmentation）与内碎片导致常驻内存集（RSS）膨胀；
- **代偿 3（缓存行污染）**：离散分配的堆地址使 CPU 预取器（Hardware Prefetcher）无法准确预测，导致 L1D/L2 缓存频繁失效。

---

## 2. 形式化论证三段论 (Formal Syllogism)

- **大前提 ($P_1$)**：系统级软件的极端吞吐与确定性低延迟要求尽量消除无谓的堆分配与内存分配锁争用。
- **小前提 ($P_2$)**：堆内存能够容纳生命周期超越单函数栈帧以及大小在编译期不可知的动态集合对象。
- **归谬 ($R$)**：若将所有数据无差别堆分配，则系统将在并发争用与内存碎片中消耗大量 CPU 周期；若完全禁止堆分配，则无法表达动态数据结构。
- **结论 ($C$)**：∴ 现代系统语言必须提供显式、精确的堆分配容器（如 `Box<T>`, `Vec<T>`），并将其置于唯一所有权与严格生命周期的约束之下。
