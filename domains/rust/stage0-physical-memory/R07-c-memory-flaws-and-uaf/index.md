# R07: 从 C 语言内存缺陷到所有权发生学：UAF、Double Free 与数据竞争

> **一手文献与源码锚点**：Bernstein (1966) 并发读写集互斥条件 · C++ 经典迭代器失效（Iterator Invalidation）· CVE-2021-3156 Linux Sudo 堆溢出漏洞分析

---

## 1. 一手原典：指针别名引发的物理内存崩溃

考察一段经典的 C++ 崩溃代码：

```cpp
#include <vector>
#include <iostream>

int main() {
    std::vector<int> v = {1, 2}; // 初始 capacity = 2
    
    // 危险：传入对容器首元素的只读引用别名 (const int&)
    v.push_back(v[0]); 
    
    // 物理层崩溃过程：
    // 1. push_back 检测到 size == capacity (2 == 2)，必须扩容；
    // 2. 内存分配器分配 4 个 int 的全新堆块；
    // 3. 将旧数据拷贝到新堆块后，立即调用 free() 释放旧堆块；
    // 4. 此时参数别名 (v[0]) 指向的内存已被归还给操作系统内核；
    // 5. 写入操作解引用悬垂指针，发生释放后使用（Use-After-Free, UAF）！
    return 0;
}
```

## 2. 核心概念发生学解析

1. **指针别名（Aliasing）的致命陷阱**：
   - 当多个指针/引用指向同一个物理内存地址时，程序失去了**引用透明性**。
   - 任何一个指针的写入操作，都会以隐蔽的“动作效应（Action at a Distance）”破坏其他指针的不变量。
2. **Bernstein 并发互斥准则**：
   - 任何两个并发访问同一个内存位置的操作，若至少有一个是写操作（$W \cap R \ne \emptyset$ 或 $W \cap W \ne \emptyset$），且缺乏同步因果序，则必然引发未定义行为（Data Race）。
3. **Rust 的第一性原理回应**：
   - Rust 并没有采用昂贵的运行时跟踪，而是在**编译期类型系统**中建立了公理化的 `Aliasing XOR Mutability`（别名异或可变性）。

---

## 3. 形式化论证三段论 (Formal Syllogism)

- **大前提 ($P_1$)**：若类型系统允许在存在指向某内存块的活动只读引用的同时对该内存块执行重新分配或写入，则指针别名失效与 UAF 具有不可避免的必然性。
- **小前提 ($P_2$)**：C/C++ 允许指针别名与就地突变（In-place Mutation）无约束共存，导致编译器无法静态验证引用有效性。
- **归谬 ($R$)**：若仅依赖程序员的“谨慎编码”与 AddressSanitizer 等事后动态插桩检测，则内存安全漏洞将永远随系统规模扩大而指数级滋生。
- **结论 ($C$)**：∴ 必须在编译期引入静态所有权系统与独占借用模型，在数学上证明别名与可变性的绝对互斥。
